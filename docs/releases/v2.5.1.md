# Coordinator v2.5.1

This patch corrects unequal returns for equal stakes, fixes settlement sweep signing, and improves entry and payout screens. Synthetic traffic now tests staggered users, abandoned entries, and submission races. These changes are in [#96](https://github.com/5day4cast/coordinator/pull/96).

**Changes**

- New contracts use equal relative weights for no-score and expiry outcomes. Three equal stakes in a 3,000-sat pool return 1,000 sats each, replacing the incorrect 1,020/990/990 split. Ranked payouts and the fee policy are unchanged.
- Existing signed contracts retain their original terms. Fully enrolled competitions without a built contract retain their accepted payout table. Missing or inconsistent authorizations stop contract creation.
- Sweep transactions sign input 0, regardless of the previous output's index. This fixes split-output and unified-close signing failures.
- Maps have clearer contrast, and competition rows fit mobile screens. Dialogs support keyboard navigation and focus management. Payout screens show exact invoice amounts, signed allocations, and distinct pot-return and escrow-refund states. A failed invoice no longer hides an unpaid entry's payout action.
- Invoice and entry deadlines apply before background workers advance competition state. Cancellation rechecks whether the roster filled. Concurrent duplicate submissions receive the normal duplicate-entry rejection.
- synth records a seed and each player's arrival, payment, and submission waits before competition creation. Concurrent players retain durable payment traces. Six cases cover full lifecycle, unpaid abandonment with replacement, paid abandonment, duplicate submissions, late submissions, and escrow refunds.
- Schedules can rotate each scenario through multiple observation durations. Two-, three-, and four-hour windows provide longer weather coverage; ten-minute windows retain short-window refund coverage. Longer windows do not guarantee scored outcomes.
- The failed-payout metric description identifies retained job records. It does not represent a count of distinct unpaid players.

**Required upgrade steps**

1. Back up the coordinator database. This release adds no database migration or authorization-schema version change.
2. Drain competitions with existing entry authorizations before accepting new entries.
3. Deploy the coordinator, browser WASM, coordinator verifier enclaves, and synth from `v2.5.1` together.
4. Check new contracts for equal refund and expiry weights before accepting payments.

Old verifier enclaves reject the new relative weights because their sum can differ from 100. The new browser rejects old unequal refund tables. Do not mix these components or authorization tables during rollout.

See [equal-refund operations](https://github.com/5day4cast/coordinator/blob/v2.5.1/docs/ops/equal-refunds.md) and [synthetic traffic configuration](https://github.com/5day4cast/coordinator/blob/v2.5.1/docs/ops/synthetic-traffic.md) for verification and timing settings.

**Validation**

Rust tests cover payout weights, legacy authorizations, sweep signing, deadline boundaries, concurrent writers, seeded plans, and submission response-loss recovery. JavaScript tests and 486 offline payout assertions passed across Chromium, Firefox, and WebKit. Formatting and Clippy passed for the affected components.

The new scenario tests use local mock services. They do not establish successful live funded runs.

**Limits**

Historical signed allocations and completed payment records remain unchanged. Historical failed payouts require separate reconciliation.

The sweep correction can let existing close and reclaim jobs progress. Reclaiming an unpaid output returns funds to the coordinator; it does not pay the player or clear that obligation.
