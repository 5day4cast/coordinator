# v2.27.20 — Back off and jitter transient wallet reads

`ark-swapd` now retries transient failures when reading a page of wallet VTXOs from the Arkade indexer. Previously, one connection reset immediately failed the wallet request and could interrupt a Synth rebalance check.

Each page gets at most three attempts. Retries use exponential backoff with equal jitter: 1–2 seconds before the second attempt, then 2–4 seconds before the third. All attempts and delays share the existing 20-second deadline. If the deadline expires during backoff, no further request is sent.

Retries apply to gRPC `Unavailable`, `DeadlineExceeded`, and `Unknown` errors with a typed transient I/O cause. Permanent errors return immediately. Payment submissions, transaction finalization, and batch operations retain their existing behavior. Reads that cannot recover still fail; they do not return a stale or zero balance.

No database migration or configuration change is required. Deploy the updated `ark-swapd` artifact to enable this behavior. Helm chart metadata and default application image tags are aligned with this release.

Validation: all 69 `coordinator-ark-swap` tests passed locally, including real gRPC connection resets, jitter ranges, request spacing, retry exhaustion, and deadline cancellation. Clippy passed for all package targets with warnings denied. The original production resets' source remains unconfirmed; this change improves local handling of brief interruptions.
