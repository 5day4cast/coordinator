# Coordinator v2.27.3

Metrics and weather refreshes read competition summaries instead of rebuilding historical signed contracts.
Automatic payout discovery selects candidate IDs before loading one contract at a time.
Player payout pages load only competitions associated with that player's entries.
Payout eligibility and expiry settlement checks remain in the domain layer.

Summary reads preserve the contract state when earlier lifecycle timestamps are present.
Regression tests compare summary-derived lifecycle counts with full competition reads.

Synth's manual run endpoint accepts `places` for queued competitions.
For a 20-entry signing check, use `scenario=queued_one_pool`, `queue_players=20`, `max_pool_players=20`, and `places=2`.
Normal pool-shape validation and current Oracle eligibility checks apply.

The changes reduce recurring contract allocations. Confirm the memory trend after deployment.
Historical coverage gaps still require source observations or the existing contract expiry/refund path.
The signing implementation and enclave protocol are unchanged from v2.27.2.
