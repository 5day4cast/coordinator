# v2.27.6 — Reduce checkpoint serialization memory

Large checkpoint byte arrays were inspected by first collecting a `Vec<&RawValue>`. On a 64-bit target, that index needs 16 bytes per array element. An 8 MiB byte payload therefore required an additional 128 MiB index before compression, besides the state and JSON buffers already in memory.

Array classification now visits borrowed values one at a time. Scalar arrays still become one compressed, authenticated part; arrays containing objects or arrays retain their previous partitioning. The checkpoint format, content digests, retry journal, and recovery behavior do not change.

An isolated comparison using the exact old expression and new classifier removed the 128 MiB temporary index for an 8 MiB synthetic payload. This identifies and fixes allocation amplification; it does not establish that every production memory increase is resolved. Coordinator 2.27.5 process, allocator, and checkpoint-size metrics remain available for verification during real signing and settlement.

Validation covers nested values, brackets within strings, malformed input, and trailing data, together with the existing encrypted checkpoint round-trip, ciphertext reuse, compare-and-swap, and compatibility tests.
