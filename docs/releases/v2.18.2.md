# Coordinator and Synth v2.18.2

This release fixes expiry progression, visitor entry pages, database access, and synth health checks.

## Coordinator

- Advance expired contracts after a successful expiry broadcast. Validate late attestations against their announced locking point.
- Explain fallback settlement as each entrant's pot share. Show usable partial-day forecast picks and clearer pool prize information.
- Show settled coordinator outputs through a cached Electrum query. This release does not sweep funds.
- Add bounded list filters, continuation cursors, conditional responses, and indexed update timestamps.
- Cache the operator inventory and move periodic database integrity scans out of health requests.
- Add a reader for compressed, authenticated checkpoint parts. The new writer remains disabled by default.

Set `COORDINATOR_PROTOCOL_PARTS=1` only after every running and rollback artifact supports the new format.
This release can serve as that compatible rollback artifact for a later release.
Disabling the writer does not convert inactive format-2 rows. The down migration refuses to discard them.
See [the checkpoint runbook](../protocol-checkpoints.md) and [list API documentation](../list-api.md).

## Synth

- Probe rendered entry forms and record persistent failures in run history and metrics.
- Use completion time and fresh payout evidence for lifecycle health.
- Preserve entry derivation IDs before requests and across retries.
- Retry transient, idempotent Keymeld reads. Follow list pagination and use event-specific queries.
- Keep open competitions available across scheduled transitions and show legacy Arkade top-ups.

Keymeld dependencies remain at the previously deployed revision. A following release updates them to Keymeld 0.8.4.
Persistent escrow state, witness identity, and sealing keys retain their existing formats and configuration.
