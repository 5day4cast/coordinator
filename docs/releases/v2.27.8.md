# v2.27.8 — Reuse unchanged checkpoint entries

The checkpoint writer caches each committed journal entry’s authenticated manifest, length, and opaque runtime revision.
Unchanged commands and signing batches skip JSON serialization and content hashing on subsequent writes.
New responses, cleared outcomes, replaced entries, and deserialized journals require fresh encoding.

The cache advances only after a successful database transaction.
Reused entries count toward the 512 MiB reconstructed-state limit.
Checkpoint formats, authentication, compare-and-swap behavior, and durable retry requirements remain unchanged.
Reloads still decode complete checkpoints, and changed large entries still need temporary buffers.

The custom Keymeld enclave shares immutable retained payloads during escrow trial transitions.
It validates the candidate before replacing live state.
Per-enclave logs expose cached response accounting, receipt bytes, preparation counts, and execution counts once per minute.
Updating the Coordinator service alone does not update these custom enclaves; deploy the matching verifier artifact as well.

Validation covers unchanged-entry reuse, reload invalidation, reconstructed size limits, failed writes, recovery round trips, and escrow retry behavior.
Production peak-memory improvements require observations after deployment.
