# Coordinator v2.13.2

This release fixes two problems in ark-swapd's refund claims ([#140](https://github.com/5day4cast/coordinator/pull/140)). The coordinator and synth are unchanged apart from the version.

**The problems**

- **The wallet lease lapsed during slow ticks.** ark-swapd renewed its 15 s lease only between worker ticks, and one tick runs the swaps, refunds, lookups and boarding in turn. A tick longer than 15 s let the lease expire mid-tick. The API then refused the coordinator's refund claims with `409 another ark-swapd instance runs the wallet`, although only one instance ran. In a blue/green deploy, another instance could also have taken over while the first was still working.
- **Two paths claimed the same refund.** The API claims a refund's swap as soon as the coordinator reports the payment, and the worker claims every paid refund. Both sent the same claim, and arkd refused the second as `INVALID_ARK_PSBT duplicated offchain tx`. Nothing was spent twice, but every claim logged a warning.

**Changes**

- `Store::keep_lease` renews the lease from its own task every second, whatever the worker is doing. The worker runs only while the last renewal held. The lease is released once the worker's last tick ends, so a clean shutdown still hands over at once.
- Claims take a lock, reload the refund inside it, and skip a refund the other path has claimed.

**Required upgrade steps**

Deploy ark-swapd from `v2.13.2`, and the coordinator and synth to keep versions together. There are no migrations or configuration changes. The verifier enclave is unchanged, so Keymeld stays on the 2.13.0 verifier.

**Compatibility**

Rolling back to v2.13.1 is safe.

**Validation**

- A new store test holds the lease through work three times its lifetime, and checks that stopping hands it over at once.
- The workspace tests and E2E suite pass in CI.
