# Coordinator v2.9.0

This release makes a failing kickoff check wait up to an hour for fees to fall before it cancels a pool. It also lets synth run competitions side by side and play more like real players ([#118](https://github.com/5day4cast/coordinator/pull/118)).

**Coordinator**

- A competition or pool whose kickoff check fails keeps checking until `kickoff_check_settings.fee_wait_secs` after registration closes. The default is 3600. It is cancelled and refunded only if it still fails then. Every way the check fails depends on the fee rate, so a pool that fails on a fee spike can still start once fees fall.
- The kickoff check in the competition API records when its wait ends as `retry_until`. Checks stored by earlier versions read without it.

**Synth**

- **Lanes.** `scheduler.lanes` sets up streams of competitions, each on its own cadence. A lane starts runs without waiting for its earlier ones, so competitions overlap. Each lane sets its scenarios, observation windows, entry window and stations; `stations_per_run` draws a few per run. A lane with `align = "utc_half"` closes entries at 00:00 and 12:00 UTC, for 12-hour day and night windows. Lanes are checked on load against the windows the oracle attests. Without lanes, the scheduler now starts runs every `interval_secs` instead of waiting that long after each run ends.
- **Overlapping runs.** Runs in progress are tracked by competition id, which synth now chooses when it plans a run. The dashboard lists every run in progress. In half-day windows, entries pick only the metrics the window scores.
- **Player counts.** Unless `defaults.users` fixes a count, each run draws one from `defaults.players`: mostly 5–10, sometimes 2–4, and 26–30 for queued splits. While the network fee is above 2 sat/vB, runs draw at least 5. A competition the coordinator still refuses as too small is recorded as a skipped creation, not a failure, and synth draws again.
- **Arrivals.** `entry_timing.arrival_pattern = "spread"` spreads players over the whole entry window, with a bunch near the deadline.
- **Other players.** People can take seats in synth's competitions. Synth players left without a seat stand down. Refund and queued scenarios accept competitions that others fill or join. Cancellations caused by others, or by the kickoff check, are followed to their refunds instead of failing the run. A competition another player won reads as paid out.

**Required upgrade steps**

Deploy the coordinator and synth from `v2.9.0`. There are no migrations. Synth configurations that set `defaults.users` keep a fixed count. Configurations that set `entry_timing.arrival_pattern` or `scheduler.lanes` need this release.

**Compatibility**

Rolling back to v2.8.1 is safe for the coordinator: pools waiting for fees are then checked once more and cancelled if they still fail. A synth configuration using lanes or `arrival_pattern` must be reverted along with synth.

**Validation**

- Coordinator tests cover the fee wait: a failed check waits until the hour is up, and never waits once it passes.
- Synth tests cover:
  - drawn counts and the fee floor
  - spread arrivals
  - 0 to 5 seats taken by others
  - others sharing or forming queued pools
  - pools cancelled by, or waiting on, their kickoff check
  - aligned lanes and half-day picks
  - two runs progressing at once, each tracked by its competition
