# v2.27.25 — Share a ten-request Ark indexer budget

Coordinator, ark-swapd, and Synth now share ten `GetVtxos` request reservations per rolling four minutes. Swapd records each reservation in SQLite before a request can start. Failed and cancelled requests keep their reservation. Restarting a service does not refill the budget.

Swapd reserves directly in its database. Coordinator and Synth use swapd's authenticated `POST /v1/indexer/permit` route. A denied or unavailable budget stops the request locally. Each gRPC page, REST page, and retry needs its own reservation. The per-process spacing and exponential failure backoff with jitter still apply. The response classification from v2.27.24 is preserved: request refusals and undecodable pages do not trigger outage backoff.

Payment checks have priority. Background reads stop when four of the ten slots are used, leaving six slots reserved for payments and refunds. Payments can use any available slot up to the total limit of ten. Unclassified reads, wallet views, maintenance, completed-swap repair, and Synth tracing are background work. Within each process, waiting payments pass queued background reads. A background quota denial cannot impose its cooldown on payment checks.

A new swap whose fresh funding check is deferred returns HTTP 503 with `Retry-After` before an invoice is issued. This avoids holding the payer's HTLC while the quota is exhausted. Existing swaps and refunds keep their retry handling.

The wallet balance view is cached for 120 seconds instead of ten seconds. Routine boarding and renewal checks run every four minutes instead of every minute. Spending still requires a fresh successful read. Swapd can start with an exhausted budget; its initial balance reading is deferred until capacity is available.

The limit can delay payment reconciliation, refunds, and balance updates. A wallet listing needs at least two requests, so ten requests do not mean ten payments. Event subscriptions can still confirm funded escrows without polling. When a fresh read is required and capacity is exhausted, the operation returns a retryable error or reaches its existing timeout. Four minutes is the quota window, not a maximum completion time.

Deploy all three services to enforce the combined limit. Migration `0008_indexer_request_budget.sql` runs automatically at swapd startup. Coordinator and Synth require access to swapd's permit route using their existing swapd token. Synth requires swapd configuration when its Ark indexer URL is enabled. During a mixed-version rollout, new callers defer requests until swapd provides the permit route. Use a recreate deployment to stop each old process before starting its replacement.

Tests cover concurrent reservations through independent SQLite pools, restart persistence, rolling-window boundaries, denied REST reads, unavailable budget services, and actual gRPC requests received by a local server. Request accounting continues at dispatch; it does not prove receipt by Arkade.
