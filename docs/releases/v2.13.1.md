# Coordinator v2.13.1

This release fixes a panic at startup in v2.13.0. The coordinator and ark-swapd could not connect to the Arkade server.

**The problem**

tonic's TLS uses rustls's process-wide crypto provider and panics when there is none. This workspace compiles in both ring and aws-lc-rs, so rustls cannot choose a provider itself, and `ArkServer::connect` installs ring.

v2.13.0 moved that install into `ArkClient::new`, which runs after ark-grpc has connected. ark-grpc's connect built its TLS config first, with no provider, so both binaries panicked at startup. The tests missed it: they build their servers offline, without connecting.

**Changes**

- `ArkServer::connect` installs the provider again before ark-grpc connects. `ArkClient::new` still installs it for clients built without connecting.
- A new test connects over TLS in a process with no provider installed and expects an error rather than a panic.

**Required upgrade steps**

Deploy the coordinator, ark-swapd and synth from `v2.13.1`. There are no migrations or configuration changes.

The verifier enclave is unchanged from v2.13.0, so Keymeld's `verifierVersion` can stay at 2.13.0.

**Compatibility**

Everything in [v2.13.0](v2.13.0.md) applies. Rolling back to v2.12.0 is safe.

**Validation**

- The new test covers the startup path the v2.13.0 tests missed.
- The workspace tests and E2E suite pass in CI.
