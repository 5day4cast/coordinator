# Coordinator v2.3.0

This release refunds the Arkade escrows of competitions that died after filling, renders the public site on the server with htmx 4, serves leaderboards from a cache with live pick progress, and lets `synth` follow each run's money to the end.

**Compatible components**

| Component | Version |
| --- | --- |
| Keymeld gateway | `v0.5.0` |
| Keymeld SDK and enclave crates | `feat/escrow-unbound-refunds` at `98f3420`, unreleased |
| Coordinator verifier enclave and LNURL relay | `v2.3.0` |
| ark-swapd | `v2.3.0` |
| synth | `v2.3.0` |
| NOAA Oracle API | `v2.0.0` or later |
| dlctix | crates.io `0.1.0` |

**Changes**

- Cleanup now finds cancelled and failed competitions funded through Arkade and refunds every escrow Keymeld can sign for, which covers competitions that filled and then died. A competition that never filled, and a ticket paid for but never entered, still can't be refunded by the coordinator; `docs/ops/stuck-escrow-check.md` lists read-only checks that find them. (#82)
- `ark-swapd` records the escrow output of a swap that settled before Arkade listed it, in a separate sweep with backoff that gives up after about two hours, behind live swaps. It records a payment attempt before sending it, so a crash or an ambiguous send error can't pay an escrow twice. (#82)
- An Arkade ticket counts only when the player's payment settled and Arkade lists an unspent output of the ticket's price at its escrow address. A competition with entries loads as collecting entries, and log lines that repeated every few seconds now appear once. (#82)
- Leaderboards and entry-form forecasts are served from a background cache of the oracle's weather, so pages no longer wait on the oracle. Ties share a rank, and picks show live progress while a competition runs: the observed value so far and whether a pick is locked in, on track, off track or out. Final scoring is unchanged and still comes from the oracle. (#80)
- The public pages are rendered on the server with maud and htmx 4. Assets are minified at build time, embedded, and served at content-hashed URLs. A strict Content Security Policy with Trusted Types applies, and the wallet's signer is no longer reachable from page scripts. Account requests are signed with NIP-98 for their exact URL; public polling is never signed. Public first-party JavaScript fell from 2,751 to 2,093 lines. (#81)
- The site explains the game, groups competitions as Live, Upcoming, Awaiting results and Finished, shows amounts in sats, and names stations by airport. The entry form has no consent checkbox; one line says where a refund goes. (#81)
- `synth` follows each run's money until payouts or refunds settle, checks who each payout paid, keeps a ledger checked against independent records, and lays out stuck money for debugging on the run page and the dashboard. `ark-swapd` can look a swap up by its payment hash. (#83)

**Required upgrade steps**

1. Back up the `ark-swapd` database. Migrations `0004_escrow_vtxo_lookups` and `0005_escrow_payment_attempts` add columns that a 2.2.0 `ark-swapd` does not know.
2. Deploy `ark-swapd` and `synth` from this release together with the coordinator. `synth` looks swaps up by payment hash, which needs this `ark-swapd`.
3. If the coordinator's wallet uses a Keymeld gateway, the public site's Content Security Policy allows that gateway's origin (`public_gateway_url`, or `gateway_url` when that is unset); check it is the origin browsers reach.
4. Optionally configure `synth`'s payee checks: `trail.payee.pubkey` (the payee node's key), `trail.payee.lnd` (its REST URL with an `invoices:read` macaroon), and `trail.arkd_url`. Without them, `synth` still confirms payouts by preimage and amount but shows the payee as not checked.

**Limits**

- Arkade funding and refunds are tested on Mutinynet only. Escrow VTXOs expire 7 days after creation.
- Competitions that never filled keep their escrowed funds until Keymeld can register a partial roster (keymeld PR #71) and the coordinator uses it.
