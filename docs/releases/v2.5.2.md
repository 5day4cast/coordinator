# Coordinator v2.5.2

This release lets operators set the coordinator fee as a percentage with up to two decimals, such as 2.5%. The change is in [#98](https://github.com/5day4cast/coordinator/pull/98).

**Changes**

- Events store the coordinator fee as integer basis points, `coordinator_fee_basis_points`, where 250 is 2.5%. The ticket price is the entry fee plus entry × basis points ÷ 10,000, rounded to the nearest sat, with exact halves rounded up.
- Event JSON also includes `coordinator_fee_percentage` for display. A whole percent is written as an integer (`10`), so clients that read an integer keep working. Other fees are written as a decimal (`2.5`).
- Requests may send either field. When both are present, they must agree.
- The admin form and `coordinator admin competitions create --coordinator-fee-percentage` accept up to two decimals. They reject more decimals instead of rounding.
- The entry form computes the same ticket price as the server.
- synth sends the fee in both fields, so it creates competitions on coordinators from before or after this release.

**Required upgrade steps**

1. Back up the coordinator database. This release adds no database migration.
2. Deploy the coordinator and synth from `v2.5.2`. The verifier enclaves and the browser WASM do not read the fee.

**Compatibility**

- Stored events keep their fee: a stored whole percent is read as that value × 100 basis points.
- Whole-percent ticket prices are unchanged, except where the exact fee ends in half a sat. The previous floating-point formula sometimes rounded those down: 50 sats at 3% cost 51 sats and now costs 52. Entry fees of 1,000–5,000 sats at 5% or 10% are unaffected.
- A coordinator older than this release rejects a decimal percentage.

**Validation**

Rust tests cover percent parsing, rounding against the previous formula for every whole percent, JSON compatibility with stored events, and the admin command's fee option. JavaScript tests cover the entry form's price, including half-sat rounding.
