# v2.27.21 — Synth fills other people's competitions

A queue that is not full starts only if it has its smallest pool, and a single competition that is not full when entries close is cancelled. Someone who enters a competition nobody else joins never gets to play. Synth can now fill those competitions.

Set `scheduler.fill` in Synth's configuration to turn it on. It runs whether or not `scheduler.enabled` starts Synth's own competitions:

```toml
[scheduler.fill]
before_close_secs = 1800   # start filling 30 minutes before entries close
check_interval_secs = 60
leave_open = 0             # seats left empty for last-minute players
min_entries = 0            # fill only competitions with this many paid entries
max_entry_fee_sats = 10000 # fill only competitions at or below this entry fee
```

Every check, Synth lists the open queues and single competitions. A run of a new scenario, `fill_competition`, takes up each competition that:

- closes within `before_close_secs`, while there is still time to pay and submit
- meets the fee and entry limits
- has empty seats
- was not made, planned or already taken up by a Synth run

The run uses the competition's own stations, fee, observation window and pick count. It counts the empty seats again, and its players arrive over the time left. A player stands down if someone else takes the seat first. Synth's players then follow the competition, or the queue's pools, to attestation, and the money trail follows the run as for any other scenario.

Pausing `fill_competition` on the dashboard stops new fills. Lanes cannot schedule the scenario. The `synth_fill_players_total` metric counts the players planned.

Only Synth changes in this release. No migration is required. Without `scheduler.fill`, Synth behaves as in v2.27.20.
