# Coordinator and Synth v2.18.4

Filtered entry lists now accept pagination parameters such as `event_id`, `limit=100`, `cursor`, and `history=true`.
The earlier query decoder rejected numeric limits when combined with the event filter, interrupting Synth pool verification and money tracking.

Synth saves each registered entry's exact submission body before payment.
After restart, a normal paid entry checks for an accepted submission and can submit its saved body while entries remain open.
Recovery preserves the planned delay, checks the deadline margin, and reconciles lost responses without requesting another ticket or repeating payment.
Skipped steps retain their status in storage and across later restarts.

Older traces without the saved submission body remain under refund tracking.
Intentional abandonment, duplicate-submission, and late-submission scenarios keep their existing behavior.
Escrow refund locktimes and failed run history remain unchanged.

Deploy both Coordinator and Synth for the entry-list and recovery fixes.
The existing Keymeld 0.8.4 gateway and 2.18.3 verifier remain compatible; this release changes neither verifier code nor persistent sealing state.
Both Coordinator 2.18.3 and 2.18.4 read the enabled format-2 checkpoints.
