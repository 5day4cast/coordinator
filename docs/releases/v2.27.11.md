# v2.27.11 — Lean competition list and checkpoint work off the runtime

The competition list no longer carries each competition's signed contract or event announcement; both are `null` in a list and remain available from `GET /api/v1/competitions/{id}`.
Competition reads group by the competition id instead of every column, so SQLite no longer sorts contract blobs per entry row.
A 50-competition list page shrinks from about 4.3 MB to about 0.8 MB, and the payouts page reads the single competition it pays.

Confidential checkpoint encoding and decoding (serde, gzip, AEAD, HMAC) run on the blocking pool instead of async workers.
Writes stay serialized; a write cancelled during encoding releases the writer unchanged, and only a committed compare-and-swap advances its cache.
A resumed writer reuses the journal entry encodings it loaded, so its first save no longer re-serializes unchanged entries.
Allocator metrics are read at most every 15 seconds, off the async runtime.

The matching verifier enclave is built with Keymeld 0.10.5: preparation-budget pressure counts retained replies only, executed preparations release their cached replies, and retained escrow state is shared instead of copied per map.

Deploy the matching custom verifier artifact and Coordinator application together.
Checkpoint formats and compare-and-swap writes remain compatible with the previous release.
