# Coordinator v3.0.0

This release settles winners automatically at their Lightning Address through participant-authorized escrow in a measured enclave.
It includes the reviewed changes from [#70](https://github.com/5day4cast/coordinator/pull/70), which supersedes #64 through #69.

**Compatible components**

| Component | Version |
| --- | --- |
| Keymeld SDK, gateway, and enclaves | `v0.5.0` |
| NOAA Oracle API | `v2.0.0` |
| dlctix | crates.io `0.1.0` |

Deploy matching coordinator, browser, Keymeld gateway, and enclave artifacts together.

**Changes**

- Winners are paid at their Lightning Address without a browser session. The payout preimage and entry key are released only against proof of Lightning payment, and each release requires its own signed consent.
- Four new crates hold the application side of the confidential protocol: `coordinator-escrow` (policy construction and contract binding), `coordinator-escrow-verifier` (the measured verifier that derives the signing plan from the bound contract), `coordinator-verifier-enclave` (Keymeld's enclave with the coordinator verifier compiled in), and `coordinator-lnurl-relay` (the enclave-terminated LNURL transport).
- The coordinator talks to Keymeld only through its confidential transport. Policies, rosters, signing messages, and results are encrypted to the attested enclave; the gateway sees routing metadata and ciphertext.
- Automatic-payout competitions are admitted before any oracle, ticket, or funding effect. The supported shape is 25 players and one winning place, set by the 2 MiB Keymeld payload limit rather than the item count. Larger shapes wait on batch chunking ([tee8z/keymeld#58](https://github.com/tee8z/keymeld/issues/58)).
- Two winning places pay 70/30 instead of 60/40, in both the server table and the browser wallet copy. This applies to every competition, not only automatic ones.
- Escrow is not created before ticket payment. The coordinator can reclaim an escrow for an unpaid ticket, and PSBT merging copies only each player's own escrow signatures.
- Held HODL invoices are released when a competition fails or expires.
- Persisted payout jobs survive restarts and retry with the same job identity. A Lightning payment hash can discharge only one entry obligation.
- NIP-98 authentication requires exact configured browser origins; wildcard origins are rejected. Per-IP rate limits and bounded replay pruning are configurable.
- Workers are supervised: a stopped or panicked worker cancels the service. The coordinator key is cached and sessions are zeroized on drop.
- Keymeld is pinned to the `v0.5.0` release tag in every manifest and the flake input.
- Dependency update: `serde_with` 3.16.1 to 3.21.0, resolving the Dependabot alert for a serialization panic in `KeyValueMap` (transitive; the coordinator does not use that type).

**Required upgrade steps**

1. Complete active competitions with the previous version before upgrading. Active keygen and signing sessions are not migrated to the confidential protocol; finish them, or cancel and refund sessions that have not committed funds.
2. Back up coordinator databases, wallet recovery material, and Keymeld gateway and enclave state. Keep the previous recovery mechanism available for completed funded contracts until settlement finishes.
3. Deploy the Keymeld `v0.5.0` gateway and, in place of the stock Keymeld enclave, the `coordinator-verifier-enclave` binary from this release's `coordinator-verifier-enclave-3.0.0-x86_64-unknown-linux-gnu.tar.gz`. It is Keymeld's enclave with the coordinator verifier compiled in, built with LNURL support, and the same archive carries `coordinator-lnurl-relay`.
4. Apply the competition and user migrations. They add the escrow, payout job, payment hash, contract binding, and Lightning Address tables and do not rewrite existing rows.
5. Replace wildcard origins in `api_settings` with the exact browser origins. Review the new `api_settings.rate_limit` and `replay_capacity` values for your proxy layout; clients behind one proxy share a bucket.
6. To enable automatic payouts, set `keymeld_settings.automatic_payouts = true` and `automatic_payout_max_fee_rate_sat_vb`, or the Helm keys `keymeld.automaticPayouts` and `keymeld.automaticPayoutMaxFeeRateSatVb`. This affects new competitions only; existing entrants cannot be enrolled after payment.
7. For Lightning Address resolution, build the coordinator enclave image with the `lnurl` feature, set `COORDINATOR_ESCROW_LNURL_ENABLED=true` in the measured runtime configuration, and run the LNURL relay on the configured VSock port.
8. Configure reviewed PCR measurements for the coordinator enclave image before mainnet use.

See [automatic Lightning Address payouts](https://github.com/5day4cast/coordinator/blob/v3.0.0/docs/PAYOUT_ESCROW.md) and [coordinator enclave and relay](https://github.com/5day4cast/coordinator/blob/v3.0.0/docs/COORDINATOR_ENCLAVE.md) for the protocol, trust boundaries, and build instructions.

**Validation and remaining limits**

The reviewed source passed 258 Rust tests and strict Clippy against Keymeld `v0.5.0`.
Keymeld `v0.5.0` passed its authorization end-to-end suites with one and three simulated enclaves.

The release workflow builds archives and images from the recorded source commit and generates package checksums.
Check the release run for build results.
The funded browser-offline payout acceptance test, deployment verification, and Nitro hardware attestation acceptance were not run for this release.
Automatic payouts default to off; enable them only after those checks pass in your environment.
