# v2.27.19 — Signing state of paid-out competitions can be deleted

The coordinator can now delete a competition's Keymeld signing state (its checkpoint, the checkpoint's parts and manifest nodes, and its refund invoice authorizations) a retention period after the competition is fully paid out. Until now it was kept forever, so the database grew with every kickoff.

A competition is fully paid out when its lifecycle is over, no contract still holds its pot, no ticket, escrow or refund still holds money, and no payout is open, held or owed. Nothing reads the state after that. See docs/protocol-checkpoints.md, "Retention".

Deletion is off by default. Each cleanup pass counts the paid-out competitions whose state is waiting out the period or due, in `coordinator_checkpoint_retention_competitions{state}`. Turn deletion on with:

```toml
[signing_state]
delete_paid_out = true
paid_out_retention_days = 3
```

New metrics: `coordinator_checkpoint_deleted_rows_total{kind}`, `coordinator_checkpoint_deleted_bytes_total{kind}`, `coordinator_checkpoint_retention_competitions{state}` and `coordinator_competitions_db_free_bytes`.

No schema changes. Synth is unchanged from v2.27.18. The verifier enclave is unchanged; keep the deployed verifier artifact.
