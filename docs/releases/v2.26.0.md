# Coordinator and Synth v2.26.0

## Request ids and client addresses

- Every request gets an id: a valid `X-Request-Id` from a trusted proxy is kept, otherwise the coordinator makes a UUIDv7. It is echoed in the `X-Request-Id` response header.
- One `http` line per request replaces the old "new request" / "response" pair: request id, parent request id (`X-Parent-Request-Id`), session id (`X-Session-Id`), client address, method, route template, status, duration and the first 16 hex characters of an authenticated pubkey. Query strings, bodies and auth headers are never logged.
- Other lines logged while a request is handled end with ` rid=<id>`.
- Calls to the oracle, the swap service and the monitoring APIs carry `X-Parent-Request-Id`, so one id finds a request across services.
- New optional `[http_context]` section: `trusted_proxies` (CIDRs) and `client_ip_header` (default `X-Real-IP`). With nothing trusted, the client address is the TCP peer.
- ark-swapd gives each request an id and writes the same `http` line. Synth's HTTP clients now send a `5day4cast-synth/<version>` User-Agent.

## Browser telemetry

- New optional `[telemetry] enabled`, off by default. When on, pages load a small script, part of the existing bundle, that sends page views, load timings (TTFB, LCP, CLS, INP), clicks on buttons and links, htmx requests and script errors to `POST /api/v1/telemetry`.
- It never reads form values. Login, sign-up, key, invoice, Lightning Address and recovery areas are excluded entirely, and the server redacts anything that looks like a key, an invoice or an email address.
- The session id lives in the tab's sessionStorage. No cookies are set.
- Caps: 500 events per session per hour and 50 per second overall. New metric: `coordinator_telemetry_events_dropped_total`.

## Feedback

- New optional `[feedback]` section, off by default. When on, a **Feedback** link in the footer opens a short form (message, optional contact), also served at `/feedback` without JavaScript.
- Abuse controls: a hidden honeypot field, a small proof of work solved while the player types, limits per session, per address and overall, and duplicate messages dropped.
- Messages are stored in the users database (new `feedback` table). The operator is alerted through ntfy, with an optional email copy, at most once every two minutes. If ntfy refuses the email, the push goes without it and email pauses for an hour.

## Operator pages

- **Feedback**: messages by status (new, seen, done), with notes and an unread count in the navigation.
- **Visitors**: search by client address, request id, session id, pubkey or username over 1 h to 7 d. Shows each session's pages, clicks, errors and slowest requests, and a merged timeline of edge requests, every service's request lines and browser events, with links to Grafana Explore. Reads logs from `[admin_settings.logs]` (`url`, `query_path`, `explore_url`).

## Upgrading

All new settings are optional and off by default; existing configurations load unchanged. Each setting can also be set from the environment (`COORDINATOR_TRUSTED_PROXIES`, `COORDINATOR_TELEMETRY_ENABLED`, `COORDINATOR_FEEDBACK_*`, `COORDINATOR_LOGS_*`); see docs/REQUEST_CONTEXT.md.
Only trust a proxy that overwrites `X-Request-Id` and the client address header on every request.
Log consumers matching the old request lines should match the `http` target.
