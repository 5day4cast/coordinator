# Coordinator v2.6.0

This release scores new competitions against NOAA Oracle's self-calibrating Par lines ([#106](https://github.com/5day4cast/coordinator/pull/106)), pins Keymeld v0.6.1, and adds the first foundations for queued competitions.

**Changes**

- **Lines scoring.** New competitions ask the oracle for `lines` scoring unless the admin form or `--scoring-rules fixed` chooses fixed rules.
  - Under lines, each station and metric has a Par band on the miss (observed minus forecast). The oracle fits the band on the station's last 60 days, so Over, Par and Under each happen about a third of the time.
  - The oracle copies the bands into the event when it is created. A right pick earns 10 points.
  - The entry form explains the rules and shows each pick's Par range around the forecast, such as `Par 67.4–70.2°F`.
  - The leaderboard and pick details score provisional points and pick states against the event's bands, and show the range.
  - Creating a lines competition fails if the oracle returns an event with fixed rules. Oracles before 2.4.0 do. A competition therefore never shows lines it will not be scored with.
  - Competitions created before this release keep the fixed rules they were created with.
- **Keymeld v0.6.1.** Every crate that names Keymeld pins the v0.6.1 release ([#107](https://github.com/5day4cast/coordinator/pull/107)).
  - Building `keymeld-enclave` now needs Rust 1.92 or newer.
  - Enclave images built from v0.6.1 have new measurements.
- **Queued competitions: foundations only.** Nothing player-facing changes.
  - The rule that splits a competition's tickets into even pools is in `coordinator-escrow` ([#102](https://github.com/5day4cast/coordinator/pull/102)); nothing calls it yet.
  - The design is in `docs/QUEUED_COMPETITIONS.md` ([#103](https://github.com/5day4cast/coordinator/pull/103)).
- **Test build.** The settlement sweep tests build against the basis-point coordinator fee again ([#105](https://github.com/5day4cast/coordinator/pull/105)).

**Required upgrade steps**

1. Deploy NOAA Oracle 2.4.0 first. With an older oracle, creating a competition fails, because new competitions ask for lines.
2. Give the oracle time to fit lines after it starts. Pooled lines exist after its first pass, and each station's own line within about two hours. Until then, a competition gets the pooled line for stations without one.
3. Publish this release before upgrading Keymeld. The verifier enclave that Keymeld's enclaves run comes from this release. Upgrade the Keymeld v0.6.1 gateway and this release's verifier enclave together.
   - Keymeld's protocol did not change, so the coordinator and gateway work across 0.6.0 and 0.6.1 in either order.
   - Don't upgrade while an Arkade kickoff is inside its batch window. Stopping the serving enclave fails that batch, and it retries.
   - Browsers check Keymeld measurements only when `crates/coordinator-wasm/keymeld-trusted-pcrs.json` lists them. If yours does, add the v0.6.1 measurements.
4. Deploy the coordinator and synth from `v2.6.0`. This release adds no database migration: a competition's scoring rules are stored with its event terms.

**Compatibility**

- Competitions stored before this release have no scoring rules, read as `fixed`, and score as before.
- Rolling back to v2.5.3 keeps settlement correct, because the oracle scores each event by its own rules. v2.5.3 would show lines competitions with the fixed-rules text and provisional scores, and would create new competitions with fixed rules.

**Validation**

Rust tests cover:

- line points and pick states against the oracle's cases, for rising and falling metrics;
- the leaderboard of a lines competition, with and without the event's bands;
- the entry form's lines text and Par ranges, and its fixed-rules text;
- posting `scoring_rules` to the oracle, and refusing a lines event from an oracle that ignores it.
