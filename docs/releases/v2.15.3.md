# Coordinator v2.15.3

This release preserves the exact floating-point values in signed oracle statements and queued competition terms when parsing JSON.

The previous parser could change a line by one unit in the last place. A valid oracle signature then failed verification and the pool retried kickoff until its deadline.

## Upgrade

Deploy the coordinator, its bundled browser WASM, synth, and the Coordinator verifier enclave from this release. The verifier must preserve the same values when it reads encrypted requests and stored receipts. The Keymeld gateway relays these payloads as opaque bytes and does not require a version change.

No database migration is included. Existing queued entries can already contain rounded terms that differ from the oracle's signed terms. This release does not rewrite their consent or bypass signature checks. Pools with inconsistent terms must use the existing failure and refund path.

## Validation

Regression coverage uses the public oracle statement from event `01a0fcbe-f701-7110-badf-62e8928d0dcd`, including its original signature. It checks JSON persistence, enclave payload decoding, and rejection of a one-bit change. The encrypted queued competition integration test also uses the decimal values that triggered the failure.
