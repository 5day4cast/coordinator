# Coordinator and Synth v2.19.0

## Competitions

The default competition is one 20-seat pool that pays two places: pools of 10 or more pay 1st 70% and 2nd 30%, and smaller pools pay their winner the pot.
Competitions paying one place may still take up to 25 players.
Signing requests are sized from each player's real scope, and a shared outcome message is permitted once per adaptor point, so a 20-player two-place pool fits one Keymeld batch.

Pool events are now listed on the oracle.
Pools used to copy their queued competition's reference event, including its unlisted flag, so the oracle's event list and status counts left out every pool.
The reference event, which takes no entries, stays unlisted. Pools formed before this release keep their existing oracle events.

Synth's default schedule runs only capped 20-entry competitions paying two places, with at least three complete entries at registration close.
Before paying, Synth checks that the coordinator returned the requested pool rules, entry cap and winning-place count.

## Players

The home page leads with open competitions, soonest first; live and finished lists are short, with search, and picks show city names.
The entry form says how many picks are required and how many are left.
Players stay logged in across reloads and new tabs until they log out or 30 days pass without a visit.
The entries page shows where an entry fee is held: the escrow VTXO, its refund transaction, and the contract funding on chain.
A Lightning Address is checked for an invoice at sign-up.

## Recovery

The coordinator can publish encrypted recovery records to Nostr relays and offer a downloadable recovery file, so a player can recover funds from their nsec alone (`docs/RECOVERY.md`). This is off by default (`[recovery]`).
The `coordinator-recover` CLI and the `/recover` page read those records without the coordinator, its database or Keymeld; the release adds the CLI for four targets and a static page archive.
Settle-only mode lets a coordinator restored from backups finish every money obligation without taking new money. It is off by default (`[coordinator_settings] settle_only = false`).
On every start the coordinator reconciles with the chain and LND: settlement transactions already on chain count as broadcast, failed payouts LND paid are marked paid, and payouts that an unrecorded LND payment could have covered are held for an operator (`coordinator admin payout-holds`).

Ticket preimages are sealed at rest with a key derived from the coordinator's existing key; no configuration changes.
A backfill seals existing rows once in the background, and older binaries stay safe during a blue/green overlap.
ark-swapd seals swap and refund preimages at rest with a key derived from its existing wallet key, backfilling at start and every 10 minutes; a rollback still starts.

## Operators

The admin create form sets picks per entry, and Discover games shows game setup and the Create competition button above the matching stations and map.
The health check returns `{"status":"ok","settle_only":…}`; the status code is unchanged.

## Deployment

This release requires Keymeld 0.9.0. Deploy the Keymeld gateway, the Keymeld enclaves and this release's verifier enclave together, before the coordinator and before any two-place pool is created; an older peer refuses the larger messages.
Deploy ark-swapd with the coordinator. Deploy Synth after the coordinator, with its existing database, so unfinished payouts and refunds continue.
Migrations `tickets_by_event`, `recovery_outbox`, `payout_holds`, the sealed ticket preimage column and ark-swapd's preimage ciphertext columns are additive and roll-forward only.
No configuration changes are required; new settings default to off. The coordinator reads LND payment history at start, which needs `offchain:read` on its macaroon.
