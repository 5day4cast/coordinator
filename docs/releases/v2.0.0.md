# Coordinator v2.0.0

This release hardens browser key custody, prevents duplicate Lightning payouts, supports NOAA Oracle 2.0, and isolates operator access.
It includes the reviewed changes from [#60](https://github.com/5day4cast/coordinator/pull/60), [#61](https://github.com/5day4cast/coordinator/pull/61), and [#62](https://github.com/5day4cast/coordinator/pull/62), plus their review fixes.

**Compatible components**

| Component | Version |
| --- | --- |
| Keymeld SDK, gateway, and enclaves | `v0.4.1` |
| NOAA Oracle API | `v2.0.0` |
| dlctix | crates.io `0.1.0` |

Deploy matching coordinator, browser, Keymeld gateway, and enclave artifacts together.

**Changes**

- Browser wallets derive entry keys and payout preimages from a private seed, network, and entry ID. Passwords and vault keys stay in WASM.
- Signed requests bind authentication to exact request bodies. Replay protection and single-use password-reset challenges prevent reused credentials from changing account state.
- Browser attestation pins, participant registration credentials, and signed roster checks protect Keymeld registration and funding. The shared session secret cannot authorize signing.
- Ticket reservations reject stale writes and rotate invoice hashes during takeover, release, and renewal.
- A persistent payout queue recovers interrupted sends. Uncertain LND responses retain the payout lock until payment status is known.
- NOAA requests use public nonce commitments and fresh authentication. Recovery checks stored event ownership, settings, and complete entry picks before accepting previous writes.
- Event validation rejects unsupported settings before allocating resources. Winner mapping follows oracle entry order and selects the matching Keymeld signing subset.
- Operator routes require authentication on a separate listener. Browser mutations require CSRF protection; mainnet excludes test invoice settlement.

**Required upgrade steps**

1. Complete active competitions with the previous version before upgrading.
2. Back up coordinator databases, wallet recovery material, and Keymeld gateway and enclave state.
3. Plan account and wallet recovery before starting this version. Login credentials, wallet backup formats, and entry-key derivation have changed.
4. Archive legacy Keymeld state and configure fresh gateway and enclave storage. Existing sessions cannot resume with the new authorization protocol.
5. Resolve duplicate entry keys, payout hashes, or multiple unfailed payouts before applying migrations. The new unique indexes reject those records.
6. Configure reviewed PCR0/PCR8 measurements for the coordinator and browser build before mainnet use. Keep simulation bypasses off mainnet.
7. Set `coordinator_settings.oracle_url` to NOAA's configured `remote_url`. Add the coordinator's Nostr public key to NOAA's `coordinator_pubkeys` allowlist.
8. Configure verified HTTPS and the correct certificate for mainnet LND. Mainnet also rejects escrow mode.

There is no automatic account, wallet, or Keymeld state reset or legacy-format conversion.
Recreate incompatible test accounts only after preserving their state and recovery material.
The entry migration removes obsolete encrypted entry-key and payout-preimage columns; preserve the original database before migration.

**Operator access and Kubernetes rollout**

- Provision a token of at least 32 characters before startup; `just admin-token` creates one locally. Configure `admin_settings.token_file` and `admin_settings.listen_addr`.
- Set `ui_settings.private_url` to the browser-facing admin origin. Use HTTPS remotely, or localhost through a port-forward.
- Route operator traffic to the separate `<release>-admin` ClusterIP Service on port `9991`. Keep the public Service and ingress for participant traffic.
- For Helm, configure `secrets.adminToken`; an external Secret must contain a `token` key. Restart the coordinator after token rotation.
- Configure synth's `config.coordinator.adminUrl` and `config.coordinator.adminTokenSecret`. Set `COORDINATOR_ADMIN_URL` and `COORDINATOR_ADMIN_TOKEN_FILE` for remote `coord` use.
- For an existing Argo CD blue/green deployment, pause automatic synchronization and participant traffic. Complete the backups before this maintenance upgrade.
- Record the public Service's active slot. Keep `blueGreen.enabled=true` and set `blueGreen.activeSlot` to that slot.
- Set `blueGreen.switchoverEnabled=false`. Apply the full v2 configuration, token Secret, admin Service, and Deployment specifications on the existing PVCs.
- The image-only PreSync hook cannot install the new admin configuration; creating the admin Service alone is insufficient.
- Verify active Deployment readiness, public health, authenticated admin access, and both Service selectors before resuming traffic.
- Preserve Argo CD ignore rules for both Deployments' `/spec/replicas` fields. Ignore `/spec/selector/app.kubernetes.io~1slot` for both the public and admin Services.
- Set `RespectIgnoreDifferences=true` in the Application's `spec.syncPolicy.syncOptions` before re-enabling the hook. Otherwise, Sync can revert the hook's changes despite ignore rules. See [Argo CD's sync option documentation](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-options/#respect-ignore-differences-configs).
- Re-enable the switchover hook and automatic synchronization after verification.

See the [upgrade and operator instructions](https://github.com/5day4cast/coordinator/blob/v2.0.0/README.md#operator-access), [wallet design](https://github.com/5day4cast/coordinator/blob/v2.0.0/docs/BROWSER_WALLET.md), and [Keymeld migration](https://github.com/5day4cast/coordinator/blob/v2.0.0/docs/KEYMELD_AUTHORIZATION_MIGRATION.md).

**Validation and remaining limits**

The reviewed source passed 158 Rust tests, Clippy, formatting, native/WASM builds, three authentication unit tests, and 37 browser scenarios.
The coordinator Helm matrix passed all 12 configurations; the synth chart also rendered successfully.
Published NOAA 2.0.0 passed event creation, announcement readback, and entry submission smoke tests.
Published Keymeld 0.4.1 passed registration-envelope preparation with simulated enclaves.

The release workflow builds archives and images from the recorded source commit and generates package checksums.
Check the release run for build results.
Funded Lightning/DLC settlement and Nitro hardware attestation acceptance were not tested.
Payout sellback still transfers secrets before payment and requires trust in the coordinator.
