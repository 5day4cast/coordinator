# v2.27.10 — Retry busy enclaves and reuse stored checkpoint parts

The matching verifier enclave is built with Keymeld 0.10.4.
When an enclave's shared preparation-reply budget is full, it now answers with a retryable busy response instead of the exhausted response.
Payout jobs stay pending and retry on a later tick; only a permission or session that has no preparations left retires a job, as before.
Keymeld 0.10.4 also hashes exact-retry metadata only for signing rounds and keygen starts, outside the session lock.

A checkpoint writer resumes from the parts it loaded and authenticated.
The first save of each Keymeld operation no longer compresses, encrypts, and inserts every unchanged part again; the compare-and-swap against the loaded version still guards every write.
Writes are typed as a whole-state or partitioned write instead of two optional values.

`COORDINATOR_PROTOCOL_PARTS` is read once at startup.
It accepts unset, `0`, `false`, `1`, or `true`; any other value stops startup with an error naming the variable instead of silently selecting format 1.
The durable signing, restart-recovery, and queued pool tests now run in both checkpoint formats and compare every stored journal with the one in memory.
The `coordinator_checkpoint_plaintext_bytes` help text now says that partitioned writes count only the bytes serialized for that write.

The automatic payout tick skips a competition that cannot be read and logs it, instead of ending the tick before due payout jobs run for every other competition.

Deploy the matching custom verifier artifact and Coordinator application together.
Checkpoint formats and compare-and-swap writes remain compatible with the previous release.
