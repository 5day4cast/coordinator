# v2.27.15 — SQLite 3.51.3, and queue details read in one batch

The coordinator, Synth and ark-swapd bundle SQLite 3.51.3 instead of 3.46.0, through sqlx 0.9.0 and libsqlite3-sys 0.37.0.
3.46.0 has a rare WAL bug that can corrupt a database; 3.50.2 through 3.51.3 also fix further WAL and locking issues.
Autocheckpoint, synchronous and busy-timeout behaviour are unchanged, and migration checksums are unchanged, so existing databases start as before.
The query planner changed between these SQLite versions, so query timings may shift.
Queries built from constants are marked as such for sqlx 0.9; `get_entry_payouts`, which nothing calls, now binds its entry id.

The operator inventory, the public competition lists and single-competition reads fetch every queued competition's settings, entries, tickets and pools in five statements on one connection, instead of five statements per queue.
`coordinator_operator_inventory_load_seconds` reports this as a separate `queues` stage; `competitions` and `queues` together equal the old `competitions` figure.

No configuration or schema changes. The verifier enclave is unchanged; keep the deployed verifier artifact.
