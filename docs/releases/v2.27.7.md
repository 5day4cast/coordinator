# v2.27.7 — Bound partitioned checkpoint allocations

The partitioned checkpoint writer borrows protocol state and serializes journal commands and signing batches individually. Journal saves reuse the unchanged application-field manifest. Committed parts skip compression, encryption, and insertion.

Every durable write retains its existing transaction and compare-and-swap checks. Failed writes do not advance the in-memory cache. The persisted format remains compatible with existing format-2 readers and rollback artifacts.

A new `coordinator_checkpoint_encode_buffer_bytes` histogram records the largest serialized plaintext buffer capacity in each partitioned write. Checkpoint encode-size samples now omit reused application fields. Decode-size samples still describe complete state.

Journal entries still serialize for hashing, complete state still decodes on reload, and individual large entries can still allocate large buffers. The default format-1 writer keeps its previous behavior. This release does not establish a safe concurrent-workload limit.

Regression coverage includes transaction failure, conflicting writers, persistence before enclave commands, restart recovery, journal replacement/removal, size limits, and rollback compatibility.
