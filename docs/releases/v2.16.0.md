# Coordinator v2.16.0

Operators can discover weather competitions and trace customer funds from Lightning payments through Arkade escrows, shared contract funding, payouts, and refunds.

## Admin workspace

- Discover games from eligible stations and forecast coverage. Filter by location, distance, observation window, and weather conditions.
- Inspect station forecasts on a map with high, low, wind, and precipitation layers. Layers use recorded forecast periods.
- Search competition, entry, ticket, payment, swap, and transaction identifiers. Expand compact nodes for retained records and current service evidence.
- Select a pool within a competition. Larger pools use compact entry rows that expand into customer flows.
- Open transaction JSON and raw hex. The operations queue identifies delayed milestones and links to chain evidence.
- Select System, Light, or Dark appearance. The browser saves the preference; entry expansion uses native HTML.
- Synth groups customer transfers by entry and pool. Optional Grafana summaries remain disabled unless configured.

## Upgrade

Deploy the coordinator, its bundled browser WASM, and synth. Keep the existing v2.15.3 signing services in place.

This release includes the v2.15.3 decimal-preservation fix. It adds no database migration or required configuration setting.

Discovery requires the oracle's `/stations/eligible` endpoint. Optional monitoring configuration is documented in `docs/ops/admin-monitoring.example.toml`.

The support pages use retained records and bounded service lookups. Missing evidence remains unknown. A write-off does not prove customer payment.

The dashboard does not execute fee bumps or recovery transactions. Forecast layers do not infer pressure fronts between stations.

## Rollback

Restore the previous coordinator and synth artifacts through the deployment controller. Database compatibility with v2.15.3 is unchanged.
