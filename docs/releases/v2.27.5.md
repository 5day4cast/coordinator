# Coordinator v2.27.5

Expose process memory, glibc allocator accounting, and confidential checkpoint sizes on the existing private metrics listener. These measurements distinguish the Coordinator process from its container's log collector and distinguish in-use allocator chunks from free arena space.

The process metrics report RSS, its high-water mark, resident anonymous pages, and swap. The allocator metrics report in-use chunks, free arena space, and total arena plus mmap space. glibc free space can include nonresident pages; it is not a measure of reclaimable RSS or proof of a leak. Unsupported process or allocator measurements remain NaN.

`coordinator_checkpoint_plaintext_bytes` records serialized checkpoint sizes with fixed `format` and `operation` labels. It observes the existing serialization buffers and adds no checkpoint serialization, contents, or session labels. Signing and settlement behavior is unchanged.

During the October 9 investigation, the two large post-restart memory jumps coincided with an older 20-player competition's attestation and payouts. Container anonymous memory then stayed near 830–843 MiB until host activation restarted it. An isolated test of eight signed-contract decodes returned live Rust allocations to its baseline after freeing the objects, but glibc retained resident pages until trimming. That proves a retention mechanism in the reproduction; it does not account for the full production peak.

The new metrics allow the next signing or payout to show whether checkpoint processing creates a large live allocation peak and whether memory remains in-use afterward. This release does not claim that the memory finding is resolved. It does not trim the live heap or change allocator settings.
