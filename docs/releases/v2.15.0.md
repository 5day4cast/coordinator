# Coordinator v2.15.0

This release requires durable payout uniqueness storage and fixes refund recovery, synthetic payment handling, settlement tracking, and payment dialog ownership.

**Required verifier upgrade**

The verifier now requires a configured payout witness before startup (#197).
SQLite records payment-hash and released-entry ownership across restarts, replacing the permanent 4,096-entry memory limit.
Missing storage, mismatched ledger identities, and unauthenticated receipts fail closed.
Restarting the enclave does not erase recorded ownership.

Choose the artifact for your deployment:

| Deployment | Release archive | Required storage |
| --- | --- | --- |
| Trusted-host TCP simulation | `coordinator-verifier-enclave-simulation-2.15.0-TARGET.tar.gz` | One initialized SQLite ledger shared by every simulated enclave. |
| Production verifier | `coordinator-verifier-enclave-2.15.0-TARGET.tar.gz` | Independently administered HTTPS witness with confidential authentication-key provisioning. |

Replace `TARGET` with `x86_64-unknown-linux-gnu` or `aarch64-unknown-linux-gnu`.
The simulation archive includes the verifier, LNURL relay, and `coordinator-payout-witness` administration binary.
Local mode requires `TRANSPORT_MODE=tcp`, explicit unattested development trust, an absolute database path, and the pinned ledger UUID.
The production archive has no local witness adapter.

Production activation still requires confidential secret provisioning and an independently administered witness.
This release does not supply a Nitro secret-provisioning mechanism.
Retained claims require complete historical reconciliation before initializing their witness.
See the [witness deployment and migration procedure](../payout-witness.md).

**Coordinator recovery and UI**

- Oracle transport, decoding, and signature errors no longer prevent an eligible signed expiry refund (#195).
- Saved expiry outcomes remain final when the Oracle recovers. Repeated settlement sweeps use the persisted outcome (#195).
- Lightning subscription failures report unhealthy state. Lifecycle workers acquire capacity before claiming a lease and renew ownership during processing (#195).
- Payment callbacks retain their ticket and form ownership. Reopened forms receive their payment result without clearing another entry dialog (#194).
- Narrow-screen entry headings no longer overlap adjacent controls (#194).
- Named operation helpers replace explicit resource drops and standalone lifetime scopes across the reviewed coordinator paths (#198).

**Synthetic traffic**

- Browser writes require an allowed Origin and a CSRF nonce. Programmatic writes require a configured bearer token (#196).
- Ticket payments validate invoice signature, network, amount, expiry, and configured fee limits before sending (#196).
- Manual and scheduled rebalances share an admission guard. Persisted payment intents prevent replacement invoices while an earlier outcome remains uncertain (#196).
- Settlement tracking follows every child pool and each accepted entry through verified payment evidence (#199).
- Contract deadlines replace the fixed eight-hour tracking limit. Unverified outcomes retain outstanding amounts and warnings (#199).
- Success metrics use persisted payout verification time. The Last Run card keeps one durable run identity across refreshes and restarts (#199).

Configure the browser origin when a proxy changes the request Host:

```toml
[server]
allowed_origins = ["https://synth.lab.tee8z.fyi:9443"]
```

Set `operator_token_file` only when programmatic writes are needed.
Use `SYNTH_OPERATOR_TOKEN_FILE` or `--operator-token-file` with the remote CLI.
See the [synthetic traffic operations guide](../ops/synthetic-traffic.md) for payment limits and uncertain-outcome recovery.

**Rollout order for the disposable-funds lab**

The lab owner authorized a fresh deployment epoch that abandons earlier fake-money claims.
An enclave restart alone is insufficient: the gateway database retains encrypted enclave identities.

1. Stop admissions, scheduling, rebalancing, and both coordinator, synth, and Keymeld slots.
2. Stop relevant replication, restoration, and database export jobs.
3. Archive old competition, gateway, and synthetic state with their SQLite sidecars and replication metadata.
4. Retire the simulated KMS master key and gateway command signing key.
5. Select new backup prefixes to prevent restoration of retired state.
6. Initialize a new witness ledger and record its printed UUID.
7. Apply the NixOS witness configuration and matching simulation artifact pin.
8. Start fresh Keymeld identities, then the coordinator, then synth.

Follow the [complete reset procedure](../payout-witness.md#fresh-start-for-the-simulated-lab) for exact state paths and initialization commands.
Keep coordinator accounts, the Oracle-authorized signer, Oracle weather history, and Lightning wallets.
The initializer refuses existing files and does not perform the external reset.

Use the module changes in [infrastructure #17](https://github.com/5day4cast/infrastructure/pull/17) for the lab's simulated enclaves.
Pin `verifierVersion` and `verifierSha256` to the simulation archive and its published checksum.
`lab-deploy update keymeld` does not update these verifier fields.
Apply changed service configuration before artifact rollout; `lab-deploy` only replaces binaries.
Deploy the coordinator and synth artifacts from this release after the verifier is ready.

**State retention and validation**

Keep the witness database and its SQLite sidecars across ordinary restarts and slot changes.
Never restore an older witness snapshot while retaining newer signing or payment state.
For existing deployments that retain claims, preserve signing evidence and reconcile uncertain payments before migration or rollback.

No local builds or tests were run during this audit and release preparation.
The release workflow builds production and simulation artifacts separately.
The new optional local adapter is compiled by the simulation release job; default PR builds do not enable it.
Existing Arkade findings remain outside this audit's scope.
