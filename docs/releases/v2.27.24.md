# v2.27.24 — Back off only when the Ark indexer struggles

In v2.27.23 every failed `GetVtxos` call started the shared backoff, including answers that only refused the request and pages the client could not decode. One malformed VTXO in a listing would have kept every `GetVtxos` call in the process at the 150–300 second ceiling, stalling wallet reads, payments and refunds while the indexer was healthy.

The guard now records a call as answered as soon as the server responds. An answer keeps the usual two-second spacing, even when it refuses the request (`InvalidArgument`, `NotFound`, `AlreadyExists`, `FailedPrecondition`, `OutOfRange`) or fails to decode. Every other failure still backs off: timeouts, connection failures, `Unavailable`, `ResourceExhausted`, internal errors, and refusals of the caller itself (`PermissionDenied`, `Unauthenticated`).

Synth's REST indexer reads follow the same rule. A 2xx response, or a 4xx other than 401, 403, 408 and 429, is an answer; those four and every 5xx response back off, as do connection failures and timeouts.

Tests run a local gRPC indexer and a local REST indexer that answer in turn with a refusal, an undecodable page and, for gRPC, an unavailable status. Only the unavailable status delays the next request.
